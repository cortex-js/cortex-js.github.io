Group Theory

The optional group-theory library adds exact permutation, finite-group, exact matrix, and polycyclic computations to the Compute Engine. It is a native Compute Engine implementation; it does not require a GAP runtime. This page describes its operators and how their values are represented. The capability and benchmark ledger describes the algorithms, measurements, and resource policies in more detail.

In the release after 0.177.0, the group operators of release 0.172.0 that started with Permutation were renamed to Group names: PermutationGroupOrder is now GroupOrder, PermutationGroupContains is GroupContains, PermutationIsSubgroup is GroupIsSubgroup, PermutationIsNormal is GroupIsNormal, PermutationGroupIsAbelian is GroupIsAbelian, PermutationGroupElements is GroupElements, PermutationGroupGenerators is GroupGenerators, PermutationGroupEqual is GroupEqual, PermutationGroupIdentity is GroupIdentity, and PermutationSubgroupIndex is GroupIndex. The new names also accept matrix groups.

Loading the library​

import { ComputeEngine } from '@cortex-js/compute-engine';
import {
  loadGroupTheory,
  type GroupTheoryLoadOptions,
  type GroupTheoryLoadReport,
} from '@cortex-js/compute-engine/group-theory';

const ce = new ComputeEngine();
const options: GroupTheoryLoadOptions = { maxChainWork: 50_000_000 };
const report: GroupTheoryLoadReport = loadGroupTheory(ce, options);
report.operatorCount; // 162

const s3 = ce.expr([
  'PermutationGroup',
  ['List', ['Permutation', ['List', 2, 3, 1]], ['Permutation', ['List', 2, 1]]],
  ['PermutationAction', 3],
]).evaluate();

ce.expr(['GroupOrder', s3.json]).evaluate().json; // 6
ce.expr(['GroupIsAbelian', s3.json]).evaluate().json; // 'False'
ce.expr(['PermutationOrbit', s3.json, 1]).evaluate().json; // ['List', 1, 2, 3]

Loading is synchronous. Repeating the call with the same effective options is idempotent. Different options on an already-loaded engine, invalid ceilings, or conflicting operator names cause the loader to throw. Loading returns a GroupTheoryLoadReport with operatorCount. Group operators are absent from the default library until loaded.

MathJSON lists start with List; tuples start with Tuple. The same operators are callable from Epsil using ordinary function calls and list literals after loading the library into that engine. Boolean results serialize as True and False. An optional mathematical result serializes as Nothing when absent.

Values and domains​

TypeMeaning
PermutationA finite-support bijection, encoded by the images of points 1..n. Trailing fixed points are removed; Permutation([]) is the identity.
PermutationActionThe declared point set 1..degree. Degree zero is allowed.
PermutationGroupA list of permutation generators and a declared action. An empty generator list gives the trivial group in that action.
GroupMatrixAn exact square matrix over the rationals (characteristic 0) or a prime field (characteristic p). Matrix values may be singular; matrix-group generators must be invertible.
MatrixGroupDimension, characteristic, and invertible generators. Empty generators still retain the field and dimension.
GroupDescriptorThe union PermutationGroup | MatrixGroup.
GroupElementThe union Permutation | GroupMatrix. Membership and domain compatibility are checked by the operation using it.
GroupHomomorphismSource and target descriptors, with complete element/image pairs.
GroupQuotientValueSource group, normal kernel, and a verified surjective projection onto the quotient representation.
GroupPcSequenceAn ambient descriptor and a validated polycyclic generating sequence in it. An induced sequence can represent a proper subgroup of that ambient group.
PcGroupA checked collected presentation of a finite polycyclic group, independent of enumeration.
PcElementA canonical coordinate vector bound to a PcGroup presentation.

Group descriptors retain generators, not a canonical name for the subgroup. Use GroupEqual(G,H) for group equality; structural equality of expressions is not a substitute. Two permutation groups must use the same action degree for group relations. Matrix domains must have the same dimension and field. The library does not silently identify permutation and matrix representations or isomorphic groups with different domains. Explicit homomorphisms can connect different representations.

Products use right actions: PermutationCompose(a,b) applies a and then b. Conjugation is x^g = g^-1 x g, and [x,y] = x^-1 y^-1 x y. Matrices act on row vectors by right multiplication. Permutation points, generator word labels, and finite polycyclic positions are one-based. Only an imported multiplication table uses zero-based element indices, with identity at index zero.

For example, Permutation([2, 3, 1]) maps 1 to 2, 2 to 3, and 3 to 1. Permutation([2, 1, 3]) and Permutation([2, 1]) are the same value, and PermutationCompose(Permutation([2, 1, 3]), Permutation([1, 3, 2])) is Permutation([3, 1, 2]). Use the named operators for these products: Multiply of two permutations is an incompatible-type error.

PermutationTransversal(G, p) returns pairs (q, t) where t maps p to q. With the right action, these t are representatives of the right cosets of the stabilizer of p. They depend on the order of the generators, and they are not always the shortest words.

PcGroup and PcElement are separate from GroupDescriptor and GroupElement. Use the Pc* operators for collected presentations. General structural queries such as GroupCenter do not yet dispatch to this representation.

Options and execution limits​

Where supported, the last argument is options: dictionary<integer>?. In MathJSON this is a dictionary value, for example:

ce.expr([
  'GroupElements', s3.json,
  { dict: { maxElements: 6, maxProducts: 12 } },
]).evaluate();

An omitted option uses the installed ceiling. A call can lower a ceiling, not raise it. Options control execution and are never stored as mathematical data in a group or map. The accepted keys depend on the algorithm and representation:

Query familyPer-call keys
GroupOrder, GroupContains, GroupIsSubgroup, GroupIndex, GroupEqual, GroupIsNormal, GroupIsAbelian on permutation groups; PermutationPointStabilizermaxWork, maxLevels, maxOrbitPoints, maxOrbitEdges, maxStoredImages; generic group queries also accept maxElements and maxPoints
GroupElements on permutation groupsmaxElements, maxProducts, maxImageWork, maxStoredImages
PermutationOrbit, PermutationOrbitsmaxPoints, maxEdges
PermutationTransversalmaxPoints, maxEdges, maxProducts, maxImageWork, maxStoredImages
Bounded finite-group, map, matrix, finite polycyclic, and section operationsmaxElements, maxWork, maxPoints; only limits relevant to the operation affect its algorithm
Collected PcGroup, PcElement, and Pc* operationsmaxWork

Permutation element operations and the three permutation constructors have no per-call options. GroupGenerators and GroupIdentity read a permutation descriptor directly; they do not build a chain or enumerate elements. Their generic signatures accept and validate the finite options for both representations. For the generic permutation chain queries, maxElements and maxPoints are accepted finite-model controls but do not cause table or action enumeration. Their effective maxWork is bounded by both maxFiniteWork and maxChainWork. PermutationPointStabilizer retains its chain-only options.

Element-count ceilings are at least one; other ceilings can be zero. Values must be safe integers within their kernel range. The finite table bound applies when the selected algorithm constructs a complete group model. Permutation chain queries, faithful finite-field matrix actions, and collected presentation arithmetic can handle orders larger than 256. Permutation GroupElements uses its separate closure bounds. A bounded structural operation can still fail on a group whose order was computed successfully.

Further fixed bounds include 4,096 enumerated subgroups, 4,096 automorphisms, one million expanded homomorphism output units per query, matrix dimension 32, and form computations in dimension at most eight. Collected presentations have rank at most 64 and at most one million logical coefficient slots including collection scratch space. Matrix coefficients and collected presentation scalar inputs have 4,096-bit bounds; some intermediate matrix elimination integers have a separate larger bound. The collected group order is an exact product and may exceed the scalar-input bit bound. Large exact results can encounter these limits before the logical work budget runs out.

A limit error is not False, Nothing, an infinite order, or a partial list. For example, a rational matrix group's closure exceeding maxElements does not prove that the group is infinite. Ordinary invalid data and exhausted budgets produce error expressions such as incompatible-type, incompatible-permutation-action, group-work-limit, finite-group-element-limit, subgroup-count-limit, automorphism-count-limit, or group-map-output-limit. Permutation algorithms also report their specific permutation-closure-*, permutation-orbit-*, and permutation-chain-* limits. Engine cancellation propagates. Unresolved valid symbolic operands remain symbolic; nested errors are preserved.

For example, the order of the symmetric group on 200 points, generated by Permutation([2, 1]) and a 200-cycle, gives the error permutation-chain-orbit-edge-limit with the default settings. After loadGroupTheory(ce, { maxChainOrbitEdges: 20_000_000 }) on a new engine, the same query returns 200!.

Work counts are deterministic operation budgets, not milliseconds. The library keeps a bounded cache of completed stabilizer chains for each engine, and reuses them across queries on the same group. Limits are not part of the mathematical value of a group.

Cancellation​

Long loops check the engine deadline, so a time limit set by the host also stops a group query. A cancellation is thrown again to the caller. It never becomes a mathematical answer or an error expression.

Diagnostics​

Errors are returned as Error expressions, for example ["Error", "'duplicate-permutation-image'"] for Permutation([1, 1]). Operand type and arity errors use the shared engine diagnostics, such as incompatible-type. An options argument that is not a dictionary is also an incompatible-type error.

An operand that is not known yet does not cause an error: a symbol with no value, or a call that contains one, leaves the query unevaluated. For example, PermutationOrder(PermutationInverse(x)) stays unevaluated until x has a permutation value.

Every code that ends in -limit and starts with permutation-, group-, finite-group-, subgroup- or automorphism- means that the computation exceeded a resource bound and gave no answer. Use a smaller input, a more suitable query, or a larger loader setting where the maximum allows it. A predicate never returns False because a limit was reached.

loadGroupTheory() throws, instead of returning an error expression, when a setting is outside its range. For example, maxChainWork: 60_000_000 throws a PermutationInputError with the code invalid-permutation-chain-work-limit.

Quotient and representation examples​

A quotient carries its projection; its group value is not itself the source group or a list of cosets:

const r = ['Permutation', ['List', 2, 3, 4, 1]];
const r2 = ['Permutation', ['List', 3, 4, 1, 2]];
const c4 = ce.expr([
  'PermutationGroup', ['List', r], ['PermutationAction', 4],
]).evaluate();
const c2 = ce.expr([
  'PermutationGroup', ['List', r2], ['PermutationAction', 4],
]).evaluate();
const quotient = ce.expr(['GroupQuotient', c4.json, c2.json]).evaluate();
const projection = ce.expr(['GroupQuotientProjection', quotient.json]).evaluate();
const quotientGroup = ce.expr(['GroupQuotientGroup', quotient.json]).evaluate();
ce.expr(['GroupOrder', quotientGroup.json]).evaluate().json; // 2
ce.expr(['GroupOrder', ['GroupHomomorphismKernel', projection.json]])
  .evaluate().json; // 2

The quotient is returned in a regular permutation representation. A lift is a chosen source representative satisfying projection(lift(q)) = q; it need not preserve multiplication. Maps serialize complete pairs, so their meaning does not depend on an internal enumeration order. GroupHomomorphismCompose(f,g) applies f first and then g; the intermediate groups must match as actual groups in compatible domains, though their generator lists can differ.

Exact rational matrices use characteristic zero:

const rotation = ['GroupMatrix', 0, ['List', ['List', 0, -1], ['List', 1, 0]]];
const matrixGroup = ['MatrixGroup', 2, 0, ['List', rotation]];
ce.expr(['GroupOrder', matrixGroup]).evaluate().json; // 4
ce.expr(['GroupMatrixDeterminant', rotation]).evaluate().json; // 1
ce.expr(['GroupOrder', ['GeneralLinearGroup', 2, 3]]).evaluate().json; // 48

Prime-field matrices reduce rational entries modulo p; denominators must be nonzero in that field. Supported prime characteristics are at most 65,521. This is not an extension-field implementation of GF(p^k). Invariant bilinear forms are matrices B satisfying g B g^T = B. Quadratic forms use upper-triangular coefficient matrices for q(v) = sum(i<=j, B[i,j] v[i] v[j]), including characteristic two. Returned bases may contain singular matrices.

A vector or projective action returns (permutationGroup, points, faithful). The permutation point numbered i refers to entry i of the returned point list (one-based). The full vector action is faithful. The projective action normalizes nonzero vectors to represent lines; it has a possible scalar kernel. Its faithfulness marker is True over F2 and Nothing over other prime fields when the subgroup's scalar kernel has not been determined. Do not use the order of that projective image as the matrix group's order without a kernel argument.

Polycyclic coordinates and collected presentations​

A finite sequence P = GroupPcSequence(G,[g1,...,gr]) uses normal forms g1^e1 ... gr^er, with 0 <= ei < relativeOrder[i]. It describes a strict subnormal cyclic series. GroupPcgs(G) computes one for a finite solvable group and returns Nothing when the complete computation proves nonsolvability. The finite sequence and its coordinate dictionary use the bounded finite model.

GroupPcPresentation(P) converts a finite sequence into checked collected relations. It preserves the order of the coordinate positions and relative orders. After conversion, Pc* arithmetic no longer enumerates the group:

const sequence = ce.expr(['GroupPcSequence', c4.json, ['List', r]]).evaluate();
const presentation = ce.expr(['GroupPcPresentation', sequence.json]).evaluate();
const x = ['PcElement', presentation.json, ['List', 1]];
ce.expr(['PcCoordinates', ['PcPower', x, 4]]).evaluate().json; // ['List', 0]

The constructor is PcGroup(relativeOrders, powers, conjugates, inverseConjugates). All four lists run from the first generator to the last. For generator gi of relative order mi, powers[i] is the tail coordinate vector for gi^mi, of length r-i-1 when indexing the input arrays from zero. Row conjugates[i] contains one such vector for each later generator gj, representing gi^-1 gj gi. inverseConjugates[i] similarly represents gi gj gi^-1. Each row has r-i-1 vectors, each of length r-i-1. The last power vector and the last two conjugation rows are empty.

Relative orders are integers at least two. Four empty lists give the trivial group. The constructor verifies the power and conjugation consistency conditions and rejects inconsistent relations; it does not complete arbitrary presentations. PcElement accepts canonical coordinates in range, not arbitrary unreduced words. PcPower accepts signed integer exponents. Arithmetic requires the same mathematical presentation; an isomorphism to a different presentation is not inferred.

const hugeCyclic = [
  'PcGroup', ['List', 1000000000000],
  ['List', ['List']], ['List', ['List']], ['List', ['List']],
];
ce.expr(['PcGroupOrder', hugeCyclic]).evaluate().json; // 1000000000000
ce.expr(['PcCoordinates', ['PcPower', ['PcElement', hugeCyclic, ['List', 42]], 3]])
  .evaluate().json; // ['List', 126]

Finite PC sifting by a subgroup H preserves the right coset Hx and yields identity exactly for membership. It is distinct from choosing the least coordinate representative of Hx. Section operations take a numerator H and a denominator N normal in H, within the parent finite sequence. Section coordinates can include relative-order-one positions. Linear actions require a nontrivial elementary abelian section whose returned coordinates form a prime-field vector basis; affine actions use homogeneous row coordinates.

To keep them readable, the trailing options: dictionary<integer>? argument is omitted wherever it is registered; the options section above identifies each family. nothing is the optional result type whose value is Nothing. Scope and references​

The only package export is the entry point @cortex-js/compute-engine/group-theory. The kernel modules under src/compute-engine/group-theory are not part of the supported API.

General structural operations can still require exponential subgroup or automorphism searches. Collected presentations currently provide arithmetic, not the full general structural API; infinite relative orders and arbitrary presentation completion are not supported. Prime-power extension fields and general infinite matrix-group algorithms are also outside this interface. See the capability ledger for measured workloads and the distinction between implemented bounded algorithms and future representation or scalability work.

For mathematical background, see the GAP reference manual, chapter 39: Groups and chapter 43: Permutation Groups. The implementation uses standard algorithms and Compute Engine conventions; it does not parse GAP programs or embed GAP code.
